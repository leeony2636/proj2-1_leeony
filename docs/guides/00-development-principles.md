# 개발 공통 원칙

## 목표

고객에게 안전하고 일관된 힌트를 제공하는 Agent를 기능별로 확장한다.

## 역할 경계

| 영역 | 담당 |
|---|---|
| 자연어 의도·감정·문장 구조화 | LLM |
| 세션·진도·시간·힌트 강도·동의·권한 | Python 코드 |
| 세션/퍼즐/힌트/직원 요청 조회·기록 | MCP |
| 화면 상태·입력·고객용 오류 표시 | Frontend |

RAG와 LangGraph는 사용하지 않는다. 승인된 정적 도메인 데이터와 코드/MCP 계약을 우선한다.

## 작업 순서

1. schema와 실패 조건 정의
2. 실패 테스트 작성
3. 최소 코드 구현
4. API/MCP 계약 테스트
5. UI 또는 Provider 연결
6. 문서·평가셋 갱신

모든 정책·보안·상태 전이 변경에는 코드 주석 또는 docstring으로 수정 사유를 남긴다.
