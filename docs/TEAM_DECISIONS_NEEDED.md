# 팀 결정이 필요한 항목

코드로 독립적으로 보완 가능한 부분은 진행했고, 아래는 실제 운영 경험/팀 정책 승인이 있어야 확정할 수 있다.

| 결정 항목 | 현재 구현 | 판단에 필요한 근거 |
|---|---|---|
| 힌트 강도 도메인 기준 | LLM이 v3 Domain Skill guidance로 `support_need` 판단, 코드는 승인 WEAK/STRONG으로만 매핑 | 실제 매장에서 약한/강한 지원을 구분했던 판단 사례와 오판 사례 |
| `15분/50%` 숫자 규칙 | 검토 후 미채택 (`DECIDED_NOT_ADOPTED`) | 향후 실제 운영 데이터가 쌓일 때 별도 재검토 가능 |
| 재요청 자동 STRONG | 미확정으로 제외 | 재요청이면 항상 승격했는지, 위치 혼동/사용법/장비 문제 예외가 있었는지 |
| 10문항 평가 | 코드가 만들지 않음 | 정상3/경계4/실패3의 입력·정답·판정 이유·판정자 |
| 30건 이상 Domain Dataset | 기존 30건은 합성 seed | 사람 판정 입력/정답/경험 근거 |
| 실제 LLM Provider/모델 | 실행 경로는 OpenRouter 지원 | 품질·지연·비용을 동일 조건에서 비교한 실측 |
| 기존 운영 요청 재촉 처리 | 상태 조회 후 LLM이 판단, 기술 idempotency는 코드 유지 | OPEN/ACKNOWLEDGED 상태에서 재촉을 새 요청으로 볼지 운영 기준 |
| Langfuse 실제 Prompt/Dataset 운영 | 코드 관측 allowlist/버전 필드 준비 | 외부 프로젝트 구성, 교체/롤백 절차, 데이터 전송 승인 |

현재 힌트 강도 정책은 **LLM 의미 판단 + 코드의 승인 콘텐츠 경계**다. 코드가 도메인상 적절한 강도까지 검증한다고 표현하지 않는다.
