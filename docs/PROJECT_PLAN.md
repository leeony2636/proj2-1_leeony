# 2차 프로젝트 기획안 - 방탈출 카페 운영 보조 Agent

## 1. 문제 정의

범용 챗봇이 아니라 현재 팀의 세션 상태, 현재 퍼즐, 이전 대화, 필요 시 조회한 힌트/운영 요청 이력을 근거로 고객 상황을 판단하고 실제 운영 도구를 연결하는 Agent를 만든다.

핵심 개선 방향은 자연어 판단을 표현별 키워드 분기나 고정 순서가 대신하지 않도록 하고, LLM의 맥락 판단이 실제 조회·질문·후속 행동에 영향을 주게 만드는 것이다. 단, 권한·스포일러·정답·상태 무결성은 LLM에 넘기지 않는다.

## 2. LLM이 맡는 판단

- 표현이 달라도 고객의 실제 의도 파악
- 독립적인 복합 요청과 하나의 문제를 다르게 표현한 상황 구분
- 최근 대화로 생략된 대상 연결
- 필요한 정보가 고객 질문인지 읽기 도구 조회인지 선택
- 힌트 이력/기존 직원 요청 상태 조회가 필요한지 판단
- 도구 결과에 따라 후속 행동 재판단
- `STANDARD/STRONG/ANSWER` 지원 필요도 판단
- 직원 전달 시 사실/시도/미확인 구분
- `applied_skill_rules`로 자신의 판단에 사용했다고 보고하는 Domain Skill rule id 기록

`applied_skill_rules`는 LLM의 자기보고 메타데이터이며, rule id 존재 확인과 실제 규칙 준수 판정은 구분한다.

## 3. Domain Skill 적용

`skills/SKILL.md`는 현장 경험 원문을 보존하고, 실제 LLM 입력은 `skills/domain_policy.json`의 버전이 있는 compact 기준을 사용한다.

- `confirmed_boundaries`: 반드시 지켜야 하는 서비스 경계
- `llm_guidance`: 현장 판단을 돕는 참고 기준
- `unconfirmed_policies`: 팀 최종 확정 전이라 자동 실행하지 않는 항목
- `visibility`: 내부 판단 전용 정보와 고객 안내 가능 범위를 구분

v3 compact policy에는 위치 혼동 상황의 지원 수준 참고 기준과 문제 번호·전체 문제 수 비공개 경계를 명시적으로 연결했다.

검토 후 채택하지 않은 항목은 `15분/50%` 숫자 기반 힌트 강도 규칙과 `재요청 횟수만으로 자동 STRONG 승격`이다. `skills/domain_policy.json`의 `DECIDED_NOT_ADOPTED` 상태를 유지하며 자동 실행 기준으로 복구하지 않는다.

## 4. 코드가 보장하는 것

- 세션/팀/테마 격리와 현재 퍼즐 순서
- 허용된 action/lookup 및 인자 검증
- 승인된 힌트만 조회/기록
- 정답 AnswerVault와 사용자 동의 경계
- 시간 연장 자동 적용 금지
- 고객 Agent의 진도 직접 변경 금지
- 상태 전이/idempotency/재시도 제한
- 실제 실행 결과와 최종 안내의 구조적 일치
- LLM 장애를 baseline 성공으로 숨기지 않음

## 5. 핵심 흐름

고객 요청 → 최소 세션 맥락 + Domain Skill → LLM 1차 판단 → 필요한 경우 읽기 도구 조회 → LLM 2차 판단 → 코드 검증 → 부작용 MCP 실행 → 확인된 결과 안내/직원 전달.

모든 요청에 2차 호출을 강제하지 않는다. 조회가 필요 없는 명확한 요청은 한 번의 LLM 판단으로 끝낸다.

## 6. 범위 제외

RAG, LangGraph, 멀티에이전트, CCTV/상시 음성 청취, 예약/결제, 자동 시간 연장, 장비 직접 제어, 미확정 긴급도/우선순위/room 매핑/통계 규칙, 승인되지 않은 자유 힌트 생성.

## 7. 평가 원칙

- 기술 검증과 실제 LLM 품질 평가를 분리
- 계획서 10문항은 정상 3 / 경계 4 / 실패 유도 3, 경계 중 최소 3개는 현장 경험자가 판정
- 30건 이상 Domain Dataset의 입력·정답·판정자는 사람이 확정
- 100건 합성 payload 테스트는 **정규화 기술 테스트**로만 사용
- 실제 모델 계약 준수율은 정규화 전 원응답과 정규화 후 결과를 구분해 기록
- 실제 서비스 흐름 평가는 초기 판단 → 선택 조회 → 후속 판단 → 실제 처리 → 최종 안내까지 본다
- 동일 입력/기준으로 baseline과 실제 LLM, 또는 변경 전후 Prompt/Skill을 비교
- Mock/합성 테스트 통과를 실제 언어 이해 품질로 표현하지 않음
